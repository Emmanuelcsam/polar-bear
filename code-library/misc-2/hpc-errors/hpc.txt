Detailed Focus on Bora Subcluster
Bora is a Sciclone subcluster optimized for multi-node parallel jobs (e.g., MPI). It uses Intel "Broadwell" processors and is paired with Hima for serial/GPU needs.

Hardware: Dell PowerEdge R630 nodes (bo01-bo55); 2x10-core Intel Xeon E5-2640 v4 @ 2.4 GHz; 64-128 GB RAM; FDR InfiniBand for apps, 1GbE for system; CentOS 7.3 OS.
Node Types: Compute nodes (bo01-bo55); properties in SLURM: bora, broadwell, c21, el7, compute.
Access/Login: SSH to bora.sciclone.wm.edu from campus/VPN/bastion. Use W&M credentials.
Intended Use: Multi-node parallel (e.g., take all 20 cores/node to avoid blocking). For fewer cores, use Hima.
Restrictions: One job/node; must request all cores (e.g., #SBATCH --partition=bora --ntasks-per-node=20); 72-hour walltime max (longer jobs queue indefinitely). Example script: Request 80 cores across 4 nodes with #SBATCH --nodes=4 --ntasks-per-node=20.wm.eduwm.edu
tcsh Shell: Usage and Configuration
tcsh (Tenex C Shell) is the primary/default shell for all HPC users at William & Mary, chosen for its compatibility with applications and to provide a cohesive environment across clusters. It's a C shell variant with features like command history, aliases, and scripting. Users can request bash via email to hpc-help@wm.edu, but tcsh is provisioned for new accounts. In SLURM scripts, specify shell with #!/bin/tcsh.wm.edu

Why Primary?: Melds disparate platforms (e.g., Sciclone/Chesapeake) into one user experience; supports Environment Modules for software management (e.g., module load intel/compiler-2024.0).
Setup/Configuration:
Files: .login (login settings), .cshrc (global env), platform-specific like .cshrc.bora (for Bora/Hima; edit to load persistent modules, e.g., add module load matlab/R2023a for auto-load on Bora logins).
System-wide: /usr/local/etc/sciclone.{cshrc,login} (Sciclone) or /usr/local/etc/chesapeake.{cshrc,login} (Chesapeake) auto-invoked.
Templates: Latest in /usr/local/etc/templates (use ls -a to view).
Modules Usage: module avail (list), module load/unload <name>, module list (current). Load in interactive sessions, scripts, or .cshrc.* for persistence.
Scripting: tcsh scripts for jobs (e.g., echo $0 confirms shell). Even tcsh users can run bash scripts.
Python/Conda: For tcsh, module load conda then create envs on front-ends like Bora.wm.edu+4 more
